# Evaluation of MT：BLEU
**BLEU**（Bilingual Evaluation Understudy）是一种自动评价指标。将机器生成的候选译文candidate translation与参考译文reference translation进行比较。通过不同长度的连续词组匹配。

**计数截断count clipping**：重复输出词的最多贡献次数不超过参考译文中它出现的次数。避免靠重复此语获得虚高分数。

BLEU由**几何平均geometric mean和长度惩罚brevity penalty（BP）组成**。候选译文明显偏短时，BP小于1，降低总分；否则BP=1

$$
 \mathrm{BLEU} = \mathrm{BP}\cdot \left(p_1p_2p_3p_4\right)^{1/4} 
$$

此处p_n就是n-gram精确率，n元词组下的匹配数/总数。

**优势**：计算快速，在一致的评价条件下，方便比较系统和实验改动。
**局限**：主要依据此面匹配，不能完整判断语义，忠实程度与表达质量。比如一些同义替换的意思相近但分数就低

**检查理解**
1. 交叉熵下降，为什么还要检查生成译文和BLEU？
	只能说明模型在训练数据上给真实目标词分配的概率提高了，不保证实际生成质量提高。比如：对新句子的泛化能力；逐词预测概率 与 整段译文质量 是两码事，衡量对象不同；。

2. 如果候选译文只翻译了参考译文开头的一段，而且这一段完全正确，为什么各阶 n-gram 精确率可能很高？BP 在这里起什么作用？
	精确率只检查**已经输出的词**中，有多少与参考译文匹配。而忽略漏译问题。
	BP会在候选译文明显偏短时降低分数，抑制这种漏译情况。

3. 一条译文大量使用了正确的同义表达，却得到较低 BLEU。你会怎样解释这个结果？
	因为BLEU主要依据词和连续词组的匹配。同义表达虽然意思正确，但用词或词序不同，就可能减少匹配。
# Attention
## why attention
**bottleneck瓶颈**：由于解码器通过编码器的最终状态来获取源句信息，需要一个**固定大小**的表示。而句子变长后需要保留的信息太多。。

## core idea
attention改变了decoder每次预测时怎样获取源句信息，增加了一条访问各个编码器隐藏状态的路径。

它保留编码器各个位置的隐藏状态，让解码器在每一步预测时，根据当前需要重新读取这些表示。

| 基本 Seq2seq      | 加入 Attention 的 Seq2seq |
| --------------- | ---------------------- |
| 解码器主要依赖源句的固定摘要  | 解码器还可以直接访问各个源位置的表示     |
| 翻译不同目标词时，源句摘要固定 | 每一步可以提取不同的源句信息         |

## working principle

| 对象                      | 含义               |
| ----------------------- | ---------------- |
| 编码器隐藏状态 h_1,h_2,h_3,h_4 | 源句各个位置的表示        |
| 当前解码器隐藏状态 s_1           | 解码器在当前预测步骤的状态    |
| 第一个目标词的预测分布 hat y_1     | 模型对目标词表中各个词给出的概率 |

1. 得到**当前解码器状态**
2. 将s_1与h_1...h_4比较，打分得到四个**注意力分数**attention scores（可以点积）
3. 4个分数进行**softmax计算**，得到4个**权重**（非负，总和为1），组成注意力分布attention distribution
4. 对**编码器隐藏状态**加权求和。得到注意力输出attention output，或称上下文向量context vector，使当前预测步骤提取的源句摘要。
5. 注意力输出 与 当前解码器状态 拼接concatenation。再用于计算目标词预测分布。
	1. 注意力输出：提供当前步骤从**源句**中提取的信息
	2. 解码器状态：包含此前**目标端**上下文等信息，反映当前生成进度。
